# 設計書：企業向けセクション ＋ 問い合わせ窓口の追加

- **日付:** 2026-06-18
- **対象:** LINK U デモサイト（Next.js 16 / React 19 / Tailwind v4、`linku-story.com`）
- **目的:** チラシのQRから来た企業担当者に「企業側のメリット」を伝え、問い合わせ・商談に繋げる

---

## 1. 背景と課題

チラシ（企業向け営業ツール）のQRコードの遷移先が本サイト（トップページ）になっている。しかし現状のサイトは学生のストーリー記事を並べた**編集メディア**であり、企業が見ても以下が分からない。

- LINK Uが企業に何をしてくれるのか（価値提案）
- 料金・仕組み・できること
- どこに問い合わせればよいか（窓口が存在しない）

結果として商談・契約に結びつきづらい。本施策でこのギャップを埋める。

## 2. ゴール（成功基準）

1. QRで来た企業が、トップページ上で「これは企業向けのサービスでもある」と数秒で気づき、企業向け情報へ進める。
2. チラシの価値提案（仕組み・できること・選ばれる理由・成果報酬0円・料金）が専用ページで一通り伝わる。
3. ページから問い合わせ・相談ができ、内容が **company@be-u.co.jp** に届く。
4. **このサイトの主役は学生のデモ記事**。企業向けの情報が記事より前に出たり、記事の体験を妨げたりしない（記事を読ませること自体が企業への最大の説得材料）。
5. 営業メール・商談で直接送れる専用URL（`linku-story.com/business`）が存在する。

## 3. スコープ外（YAGNI）

- 自前サーバーでのメール送信（外部フォーム埋め込みで実現するため不要）
- 企業向けコピーのCMS化（データモジュールに直書き）
- アクセス解析・コンバージョン計測（将来の拡張候補）
- 多言語対応、既存の記事ページのリデザイン

## 4. 確定済みの方針（ブレストでの合意事項）

| 項目 | 決定 |
|---|---|
| デザイン方向 | **A：上品な既存トーン＋ブランド差し色（ブルー）**。CTA/ヒーローに力強さが欲しい場合は部分的にBの要素を取り込み可 |
| 構成 | **専用ページ `/business` を新設**し、企業向けの売り込み（仕組み・料金・問い合わせ）はそちらに集約。**トップは学生記事を主役に保ち**、企業導線は記事一覧の“後ろ”の控えめなバンド＋ナビ/フッターに留める（記事より先に営業を出さない） |
| 問い合わせ | **外部フォーム埋め込み（Tally 推奨）**。回答は company@be-u.co.jp へメール通知 |
| 料金表示 | チラシと同じく**掲載する**（ライト15万／スタンダード30万・成果報酬0円） |
| 転送先 | company@be-u.co.jp |

## 5. デザイン方針（A案）

既存の編集デザインを土台に、信頼感のあるブルーを差し色として使う。

- ベース：白背景・濃グレー文字（`#111`）・Noto Sans JP・余白広め・細い区切り線（既存の `max-w-6xl mx-auto px-6`、`tracking`、薄いボーダー等の作法を踏襲）
- 差し色（ブランド）：`--color-brand: #1d4ed8` を `globals.css` の `@theme` に追加し、Tailwind v4 の `text-brand` / `bg-brand` / `border-brand` として利用。ラベル、重要数値、CTAボタン、セクションのアクセントに使う
- にぎやかにし過ぎない：黄色（チラシのイエロー）は原則使わず、必要なら CTA の一点アクセント程度に留める

## 6. サイト構成と変更点

### 6.1 ルーティング
- 新規ルート：`src/app/business/page.tsx`（サーバーコンポーネント／静的生成）。`export const metadata` で企業向けのタイトル・説明を設定
- 問い合わせセクションに `id="contact"` を付与し、`/business#contact` でディープリンク可能にする

### 6.2 新規コンポーネント（`src/components/business/`）
チラシの流れに沿った10ブロック。各ブロックを独立コンポーネントにし、責務を1つに保つ。

| # | コンポーネント | 内容 |
|---|---|---|
| 1 | `BusinessHero.tsx` | 「待つ採用から、声をかける採用へ。」＋主CTA（お問い合わせ） |
| 2 | `PainPoints.tsx` | こんなお悩みは？（3課題） |
| 3 | `MarketStats.tsx` | 採用環境の数値（8.98倍 / 33%減 / 51.7%）＋出典注記 |
| 4 | `HowItWorks.tsx` | LINK Uの仕組み（学生→プラットフォーム→企業） |
| 5 | `CompanyCapabilities.tsx` | 企業ができること（学生DB検索 / スカウトDM / 面談・イベント / PR記事） |
| 6 | `WhyChosen.tsx` | 選ばれる理由（本音のストーリー / 会う前から相互理解 / 卒業後もつながる地域人材DB） |
| 7 | `ZeroFeeBanner.tsx` | 成果報酬0円の強調バナー |
| 8 | `PricingPlans.tsx` | 料金プラン（ライト/スタンダード） |
| 9 | `StudentArticlesCTA.tsx` | 「実際の学生の記事を読む」→ トップ/記事一覧へ誘導（＝証拠） |
| 10 | `ContactSection.tsx` | 問い合わせ・相談フォーム（Tally埋め込み）＋運営者情報 |

### 6.3 トップページ（既存への追加）
**方針：トップの主役は学生記事。企業要素で記事の体験を妨げない。**
- `src/app/page.tsx`：`HeroSection` → `SearchableArticleGrid`（記事一覧）の**後**に `CompanyBand` を挿入（記事を一通り見てもらった後に企業導線を出す）
- 新規 `src/components/home/CompanyBand.tsx`：記事を読ませる方向の文言。「採用ご担当者の方へ。記事を読んで、気になる学生に会いに行けます。」＋［企業の方へ → /business］［お問い合わせ → /business#contact］。A案トーンの控えめなバンド
- ヒーロー・記事一覧は現状のまま変更しない（記事が最初に・大きく出る状態を維持）

### 6.4 ヘッダー / フッター
- `Header.tsx`：ナビに「企業の方へ」（→ `/business`）を追加（デスクトップ／モバイル両方）。「お問い合わせ」も追加可
- `Footer.tsx`：企業の方へ / お問い合わせ への導線と運営者情報を追加
  - 運営：株式会社be U（company@be-u.co.jp）
  - 販売：NPO法人新潟ウェイ・オブ・ワーク（company@niigata-wow.jp）

## 7. コンテンツ（データ）モデル

既存の `src/lib/data/*.ts` 方式に倣い、企業ページのコピーを **`src/lib/data/business.ts`** に型付き定数として集約する（コンポーネントは表示に専念、文言は一箇所で編集可能）。

- `painPoints: { text: string }[]`
- `marketStats: { value: string; unit: string; label: string; note: string }[]`
- `capabilities: { title: string; desc: string }[]`
- `reasons: { title: string; desc: string }[]`
- `plans: { name: string; price: string; target: string; features: { label: string; note: string }[]; popular?: boolean }[]`
- `operator`（運営／販売の会社名・電話・メール）

文言はチラシ記載を正とする（数値の出典注記、料金プランの内訳、成果報酬0円の注記を含む）。実装時にチラシから正確に転記する。

## 8. 問い合わせフロー（Tally埋め込み）

```
来訪者 → /business#contact の Tally iframe に入力・送信
      → Tally バックエンドが受信
      → メール通知 → company@be-u.co.jp
```

- 自社サーバーを経由しない。個人情報を自前で保存しない。APIキー・秘密情報をコードに持たない。
- 埋め込みは `ContactSection.tsx`（クライアントコンポーネント）で Tally の標準埋め込み（`data-tally-src` の iframe ＋ `widgets.js` による自動リサイズ）を使用。
- **フォームIDは設定値として外出し**：`process.env.NEXT_PUBLIC_TALLY_FORM_ID`（公開値・秘密ではない）で受け取り、未設定時はプレースホルダーにフォールバック。
- **常設のフォールバック**：フォーム下に `mailto:company@be-u.co.jp` の直接リンクを常に併記。フォームID未設定・スクリプト読込失敗でもページは壊れず、必ず問い合わせ手段がある。

### 利用者（依頼者）側の準備（実装後の1回設定）
1. Tally でフォームを作成（会社名・担当者名・メール・電話・希望プラン・相談内容 等）
2. フォームの通知先メールを **company@be-u.co.jp** に設定
3. フォームIDを `NEXT_PUBLIC_TALLY_FORM_ID` に設定（`.env.local` ／ Vercel の環境変数）

> Google フォームでも代替可能（その場合は iframe 埋め込み。枠が目立ち統一感はやや弱い）。

## 9. デプロイ・設定への影響

- サーバーランタイムの変更不要。現状の Next.js 構成のまま動作（埋め込みはクライアント側 iframe のため、将来 static export に変えても動く）。
- `next.config.ts` の変更不要（next/image ではなく素の iframe のため `remotePatterns` 追加不要）。
- 追加環境変数：`NEXT_PUBLIC_TALLY_FORM_ID`（公開・非機密）。

## 10. エラーハンドリング / エッジケース

- フォームID未設定 → mailto フォールバック文面を表示
- Tally スクリプト読込失敗 → iframe は最低高さで表示継続。下部の mailto リンクで担保
- レスポンシブ：全セクションでモバイル1カラム→md以上で多カラム（既存パターン踏襲）
- アクセシビリティ：見出し階層・コントラスト（ブルーは白背景で十分なコントラスト）・リンク文言を明確に

## 11. 検証方法

本プロジェクトにはテストフレームワークが未導入（テスト依存なし）。よって検証は以下で行う。

- `npm run build` がエラーなく成功
- `npm run lint` が通る
- `npm run dev` で目視確認：
  - トップ `/`：ヒーローと記事一覧の間に企業バンドが表示され、リンクが `/business` / `/business#contact` に飛ぶ
  - `/business`：10ブロックが順に表示、料金・成果報酬0円が記載どおり、`#contact` で問い合わせ位置にスクロール
  - フォーム：ID設定時は埋め込み表示、未設定時は mailto フォールバック表示
  - ヘッダー／フッターに企業導線・運営者情報
  - モバイル幅でレイアウト崩れがない

## 12. 未確定・要確認事項

- Tally フォームの入力項目（最低限：会社名／担当者名／メール／電話／相談内容。必要なら希望プラン）
- ヘッダーに「お問い合わせ」も出すか（「企業の方へ」だけに絞るか）
- 既存ヘッダーの「インタビュー／人物／タグ」は現状すべて `/` リンクのプレースホルダー。今回の対象外だが、企業導線追加のついでに軽微整理するかは別途判断
