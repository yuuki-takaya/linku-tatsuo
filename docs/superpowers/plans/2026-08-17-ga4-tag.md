# GA4（gtag.js）導入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** LINK U デモサイトの全ページに GA4（測定ID `G-M4W6JX6LX5`）のタグを組み込み、本番環境でのみアクセスを計測できるようにする。

**Architecture:** `next/script` を `strategy="afterInteractive"` で使う Server Component（`GoogleAnalytics`）を1つ作り、ルートレイアウトの `<body>` 内に置く。ルートレイアウトは全ルートに適用されるため、この1箇所で全ページがカバーされる。測定IDは `src/lib/data/analytics.ts` の定数として管理し、コンポーネントは `process.env.NODE_ENV !== "production"` のとき `null` を返してローカル開発のアクセスを除外する。

**Tech Stack:** Next.js 16.1.6（App Router）／ React 19.2.3 ／ TypeScript 5 ／ `next/script`

**元の設計書:** [docs/superpowers/specs/2026-08-17-ga4-tag-design.md](../specs/2026-08-17-ga4-tag-design.md)

## Global Constraints

- 測定ID は **`G-M4W6JX6LX5`**。ハードコードしてよい（ページソースに必ず露出する公開情報であり、シークレットではない）。環境変数は使わない。
- 計測は **本番ビルドのみ**（`process.env.NODE_ENV === "production"`）。`npm run dev` では一切のリクエストを飛ばさない。
- スクリプト読み込みは **必ず `next/script`** を使う。生の `<script>` タグを JSX に書いてはいけない（React が通常の要素として扱い、`async` 属性や2つのスニペットの実行順序が保証されないため）。
- コメントは日本語、識別子は英語（プロジェクト共通規約）。
- **このプロジェクトにはテストフレームワークが存在しない**（`package.json` に `test` スクリプトなし、テストファイルなし、jest/vitest/playwright いずれも未導入）。本計画のためにテスト基盤を導入しない。検証ゲートは `npm run build` / `npm run lint` / ブラウザの Network タブでの実測とする。
- パスエイリアスは `@/*` → `./src/*`（`tsconfig.json` で定義済み）。
- 手動の `page_view` 送信ロジック（`usePathname` を使うもの）は実装しない。GA4 の拡張計測機能に任せる。

- [ ] **Step 2: GA4 コンポーネントを作る**

`src/components/analytics/GoogleAnalytics.tsx` を新規作成する。`analytics` ディレクトリも新規に作る必要がある。

```tsx
import Script from "next/script";

import { GA_MEASUREMENT_ID } from "@/lib/data/analytics";

/**
 * GA4（gtag.js）を読み込むコンポーネント。
 *
 * 本番ビルドのときだけスクリプトを出力する。ローカル開発（npm run dev）の
 * アクセスが GA4 の計測データを汚さないようにするため。
 * Vercel のプレビューデプロイは production ビルドなので計測対象に含まれる。
 *
 * 状態も対話も持たない Server Component のため "use client" は不要。
 */
export default function GoogleAnalytics() {
  if (process.env.NODE_ENV !== "production") {
    return null;
  }

  return (
    <>
      <Script
        src={`https://www.googletagmanager.com/gtag/js?id=${GA_MEASUREMENT_ID}`}
        strategy="afterInteractive"
      />
      <Script
        id="google-analytics"
        strategy="afterInteractive"
        dangerouslySetInnerHTML={{
          __html: `
            window.dataLayer = window.dataLayer || [];
            function gtag(){dataLayer.push(arguments);}
            gtag('js', new Date());

            gtag('config', '${GA_MEASUREMENT_ID}');
          `,
        }}
      />
    </>
  );
}
```

実装上の注意:
- `next/script` のインラインスクリプトには **`id` 属性が必須**。無いと Next.js が警告を出し、スクリプトの重複読み込み防止が効かない。`id="google-analytics"` を必ず付けること。
- 2つの `<Script>` はどちらも `strategy="afterInteractive"`。ハイドレーション直後に、記述順で実行される。
- `process.env.NODE_ENV` は Next.js がビルド時に静的な文字列へ置換する。`next build` では `"production"`、`next dev` では `"development"` になる。

```bash
npm run build && npm run start
```

期待する結果: `http://localhost:3000` で起動する。ポート 3000 が使用中の場合は 3001 にフォールバックするので、実際に表示された URL を使う。

- [ ] **Step 2: gtag.js が読み込まれることを確認する**

ブラウザで起動した URL（`http://localhost:3000`）を開き、DevTools の Network タブを開いた状態でリロードする。

期待する結果: `https://www.googletagmanager.com/gtag/js?id=G-M4W6JX6LX5` へのリクエストが **Status 200** で発生している。

確認できない場合の切り分け:
- リクエストが全く無い → `NODE_ENV` が production になっていない（`npm run dev` を起動していないか確認）、またはコンポーネントがレイアウトに組み込まれていない

- [ ] **Step 3: page_view が送信されることを確認する**

同じ Network タブで、フィルタに `collect` と入力する。

期待する結果: `https://www.google-analytics.com/g/collect?...` へのリクエストが発生しており、クエリパラメータに `tid=G-M4W6JX6LX5` と `en=page_view` が含まれている。

- [ ] **Step 4: クライアントサイド遷移が計測されることを確認する**

Network タブのフィルタ `collect` を維持したまま、トップページのヘッダーまたは記事一覧下部のバンドから `/business` へのリンクをクリックする（ページ全体がリロードされない、App Router のクライアントサイド遷移になっていること）。

期待する結果: 遷移後に `g/collect` へのリクエストが**追加で**発生し、`dl`（document location）パラメータが `/business` を指している。

これが発生しない場合: GA4 管理画面の「管理 → データストリーム → 該当ストリーム → 拡張計測機能」で「ブラウザの履歴イベントに基づくページの変更」が ON になっているか確認する。これは**コードではなく GA4 側の設定**であり、デフォルトで ON。OFF だった場合は ON にして再確認する。ON でも計測されない場合のみ、手動送信の実装を別途検討する（本計画のスコープ外。ユーザーに報告して判断を仰ぐ）。

- [ ] **Step 5: 開発環境では計測されないことを確認する**

本番サーバーを停止（Ctrl+C）し、開発サーバーを起動する。

```bash
npm run dev
```

ブラウザで開発サーバーの URL を開き、Network タブでフィルタに `googletagmanager` と入力してリロードする。

期待する結果: `googletagmanager.com` へのリクエストが **1件も発生しない**。ページの HTML ソース（View Source）にも `gtag` の文字列が含まれない。

発生してしまう場合: `GoogleAnalytics.tsx` の早期 return の条件式が `!==` になっているか確認する（`===` にすると逆になる）。
